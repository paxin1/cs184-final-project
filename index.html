CS 184 Final Project Proposal - Fall 2026

Stable Lighting

Stackable post-processing shaders for Star Stable Online in ReShade

Laura Nagamine, Patrick Xu, Elena Lepe, Oscar Mendoza-Oliva

Summary

We're writing a set of ReShade shaders that run on top of Star Stable Online and change how the game looks without touching its code. Using the frame's color and depth buffers, we'll add ambient occlusion, bloom, depth of field, anti-aliasing, and color grading as separate passes that can be stacked into a few different presets.

Problem Description

ReShade hooks into a game's graphics API and lets you run your own shaders on each frame right before it's shown on screen. People use it to make older games look better, but the shader only gets the finished image, and usually the depth buffer. There are no normals, materials, or light positions. So anything that depends on scene geometry has to be rebuilt from depth. We'll linearize depth, reconstruct view-space positions, and estimate normals from neighboring depth values.

This is hard for a few reasons. Screen-space effects can't see anything off-screen or behind other objects, which leads to halos around edges and AO that fades out near the borders of the screen. Things that don't write depth, like the UI, particles, and alpha-tested hair or horse manes, will break the depth-based effects unless we handle them. Everything also has to run in real time on top of the game, so we'll be trading sample counts and resolution against frame time. Finally, the effects affect each other. AO needs to happen before bloom, and DoF should blur the result after that. A bad pass order or the wrong color space can make the combined result look worse than any one effect alone.

Our plan is to write one shared header (depth, positions, normals, debug views) and build each effect as its own ReShade technique on top of it. A preset is then just a pass order plus parameter values.

The biggest risk: ReShade can turn off depth buffer access in online games when it sees network traffic, and most of our effects need depth. The first thing we'll do is check whether depth works in Star Stable Online. If it doesn't, we'll develop and test the depth effects on a single-player DX11 game or a small test scene. Bloom, AA, and color grading only need the color buffer, so those will still run on Star Stable.

Goals and Deliverables

The final demo is live gameplay with the ReShade overlay open. We'll ride around, toggle individual effects, and switch between presets while the frame time shows on screen. Alongside the demo we'll have before/after screenshots from fixed camera positions and a short video.

Measuring quality and performance

  • GPU time per effect and for the whole stack at 1080p, using ReShade's performance stats. We'll note which GPU each number came from. We'd like the full baseline stack to cost under about 5 ms.
  • For AO and DoF, we'll run each shader with very high sample counts to get a reference image, then compute PSNR/SSIM of our real-time settings against it.
  • Side-by-side comparisons and zoomed crops (especially for AA and depth edges), plus notes on artifacts we see, like halos, banding, flickering in motion, and effects bleeding onto the UI.

Questions we want to answer

  • How close can we get to "modern" lighting with only color and depth?
  • How good are normals reconstructed from depth, and how much does their error show up in AO?
  • For each effect, at what point do more samples stop making a visible difference?
  • What pass order (and linear vs. gamma space) gives the best combined look?
  • Where does plain ReShade stop being enough, and what extra data would we need?

(1) Baseline plan

  • Shared header: depth linearization, position/normal reconstruction, debug views
  • SSAO (horizon-based) with a depth-aware blur
  • Bloom with a soft threshold and a downsample/upsample blur chain
  • Depth of field with an adjustable focus distance and a gather-based blur
  • Post-process anti-aliasing (FXAA/SMAA style edge detection)
  • Tonemapping, LUT color grading, vignette, and film grain
  • At least three presets that combine the passes in different ways
  • Demo, comparison images, performance numbers, and the final writeup

(2) Aspirational plan

  • Screen-space GI: ray march the depth buffer for one bounce of indirect color
  • Volumetric fog and light shafts, maybe with animated noise for mist or clouds
  • Temporal accumulation so AO/GI can use fewer samples per frame
  • A ReShade add-on (or fork) that exposes more than color and depth, like normals or HDR color. We'd only try this on an offline test target.

Computing platform, hardware, and software

ReShade only runs on Windows, so development and testing will happen on our Windows PCs with discrete GPUs. The shaders are written in ReShade FX, which is basically HLSL. We'll also use RenderDoc to debug frames, OBS to record video, Python (scikit-image) for PSNR/SSIM, and GitHub for version control.

Existing code

We're building on ReShade. It handles hooking into the game, the in-game UI, and running effects, and its ReShade.fxh header gives us depth buffer access and fullscreen passes. We'll look at the official reshade-shaders repo for conventions and how the API is used, but we're writing the effects ourselves.
